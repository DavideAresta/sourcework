# SourceWork

**Turn meeting recordings, PDFs, wireframes and wiki pages into a Product
Requirements Document where every requirement cites the thing that justifies
it — and no model can invent a citation.**

[![Licence: MIT](https://img.shields.io/badge/licence-MIT-blue.svg)](LICENSE)
[![Python 3.11+](https://img.shields.io/badge/python-3.11%2B-blue.svg)](pyproject.toml)
[![A2A v1.0](https://img.shields.io/badge/A2A-v1.0-4b32c3.svg)](https://a2a-protocol.org)
[![No API key required](https://img.shields.io/badge/API%20key-optional-success.svg)](docs/backends.md)

Eight agents, each an independently deployable [A2A](https://a2a-protocol.org)
service. Runs entirely on your own hardware if you want it to — your documents
never have to leave the machine.

## The one idea worth knowing

Nothing enters the pipeline except **evidence**: an atomic, quotable claim with
a locator (`p.12`, `00:14:32`, `slide 4`) pointing back at where it came from.
Requirements cite evidence ids, and **citations are validated in code** — a
model that invents an id loses it, and any requirement left uncited is forced to
render as `derived`, meaning *inferred, not stated*.

Be precise about what that guarantees, because the difference matters when you
are the one signing the document. **Enforced:** every citation resolves to
evidence that really was extracted, invented ids are dropped, uncited
requirements are marked. **Not enforced:** that the cited evidence actually
*supports* the claim. No mechanical check catches that — the traceability matrix
exists so a human can, in one pass, with the quote next to the requirement.

### Why not just paste the documents into a chat model?

You can, and for one short document you should. The difference shows up at five
sources and two hundred claims: a chat model will happily attribute a
requirement to a meeting that never discussed it, and nothing in the transcript
tells you which ones it did that to. Here, an invented citation cannot survive —
it is dropped in code before you ever read it — and the requirement it was
propping up is visibly marked as inferred instead.

## What it produces

A real PRD from the five-file demo pack, generated by the command below and
committed unedited: [examples/sample_output/](examples/sample_output/). 59
requirements from 170 pieces of evidence across a PDF, a second PDF that
contradicts it, a meeting recording, refinement notes and a wireframe.

Every requirement carries the quote that licenses it, and the position to go and
check — a page for a document, a timestamp and a speaker for a meeting:

| Requirement | Source | Location | Evidence |
|---|---|---|---|
| REQ-015 | 02-it-architecture-constraints.pdf | p.1 | Deployments are blocked between 15 December and 6 January, the peak trading freeze. |
| REQ-015 | 03-kickoff-meeting.vtt | 00:06:06 Lena Fischer | There is a deployment freeze from the fifteenth of December to the sixth of January. |
| REQ-025 | 03-kickoff-meeting.vtt | 00:01:31 Sofia Greco | The company cannot offer thirty days and then quietly withdraw it for some customers. |

And where the model reasoned rather than read, the document says so:

| ID | Pri | Requirement |
|---|---|---|
| REQ-032 | SHOULD | **Peak return-volume capacity** `derived`<br>The system must handle at least twice the baseline monthly return volume (approximately 16,400 returns in a peak month). |

Nobody in that meeting said "16,400". Two people said *"about 8,200 returns per
month"* and *"return volume more than doubles in January"* — the number is the
model's arithmetic, and the `derived` tag is the PRD telling you to check it.

## Quick start

```bash
make install                 # venv + editable install
make demo                    # the full pipeline, no API key, no model needed
```

`make demo` runs all eight agents over real HTTP and real A2A with a stub model,
so you can see the whole thing work before deciding whether to give it
credentials.

Then point it at something real:

```bash
sourcework app               # the whole mesh + web UI in one process
sourcework doctor            # what is configured, and what is actually reachable
```

Or from the command line:

```bash
sourcework generate "Invoice reconciliation" \
  -i ~/meetings/kickoff.vtt \
  -i ~/docs/rfp.pdf \
  -i ~/designs/checkout-flow.png \
  -q 'space = PRD AND text ~ "reconciliation"' \
  --publish --space PRD
```

A run takes minutes, so it is interruptible: Ctrl-C stops the work rather than
orphaning it, everything finished is checkpointed, and `--resume` picks up where
it left off. See [docs/using-it.md](docs/using-it.md).

## An API key is optional

If you are signed into a coding CLI, the entire pipeline runs on that
subscription with nothing plumbed through SourceWork:

| Backend | Auth |
|---|---|
| `claude-code` | the CLI's own login |
| `opencode-cli` | OpenCode's provider config |
| `copilot-cli` | `copilot login` |
| `codex-cli` | `codex login` |
| `agy-cli` | its own sign-in |
| `litellm` | any hosted provider, if you'd rather |

```bash
sourcework backends          # what is usable on this machine
```

Models are chosen per role — a cheap one for extraction, a strong one for the
analyst, a *different family* for the critic so the review is adversarial rather
than agreeable. Backends fail over when one hits a usage limit.
See [docs/backends.md](docs/backends.md).

## Or entirely on your own hardware

Every model can be local. The `litellm` backend speaks to any OpenAI-compatible
server, so [llama.cpp](https://github.com/ggml-org/llama.cpp) is a
configuration change, not a code change:

```bash
SOURCEWORK_LLM__BACKEND=litellm
SOURCEWORK_LLM__API_BASE=http://127.0.0.1:8081/v1
SOURCEWORK_LLM__DEFAULT_MODEL=openai/<model-id>
```

Schemas are grammar-constrained rather than described, so malformed JSON is
impossible rather than unlikely. `scripts/llama-models.py` finds the GGUFs you
already have, says which ones fit your card, and generates a
[llama-swap](https://github.com/mostlygeek/llama-swap) config so roles can use
different models behind one endpoint. The four things that decide whether a
local run works at all are written down in
[docs/local-models.md](docs/local-models.md).

## The mesh

| Agent | Port | Does |
|---|---|---|
| **Orchestrator** | 8000 | Routes inputs, sequences the pipeline, runs the review loop |
| **Document Ingestor** | 8001 | PDF, DOCX, PPTX, XLSX, CSV, HTML, MD, TXT → evidence |
| **Image Analyst** | 8002 | Mockups, screenshots, whiteboards, diagrams → evidence |
| **Meeting Analyst** | 8003 | VTT/SRT/JSON transcripts → evidence + decision log |
| **Confluence Connector** | 8004 | CQL search, page + attachment read, idempotent publish |
| **Requirements Analyst** | 8005 | Cluster, de-dup, MoSCoW, conflicts, open questions |
| **PRD Writer** | 8006 | Narrative + Markdown + Confluence storage XHTML |
| **PRD Critic** | 8007 | Deterministic traceability checks, then adversarial review |

Every agent serves `/.well-known/agent-card.json`, `/healthz` and `/docs`, so
any A2A client can drive the mesh — the web UI is one such client, not a ninth
agent. See [docs/a2a.md](docs/a2a.md) for the Python and raw JSON-RPC calls.

Or in containers:

```bash
docker compose up -d --build
curl localhost:8000/.well-known/agent-card.json
```

## Security

The UI has **no authentication** and its settings endpoint rewrites `.env`,
provider keys included; the runs endpoint returns the full text of everything
you have ingested. It binds `127.0.0.1` for that reason — bind wider only behind
a proxy that authenticates. The agent mesh ships with a shared default secret
and `ENFORCE=0`, which is fine on a laptop and wrong on a shared network. See
[SECURITY.md](SECURITY.md).
